# Lectura de pagos y apertura de Nueva venta

Medición real previa: lector 2613ms, de los cuales autorización final728ms y segunda búsqueda de contexto/propiedad472ms. Snapshot554ms y validación de fuentes342ms. Los tiempos acumulados de lecturas paralelas no se suman para deducir la latencia total. Sólo se registran nombres fijos de tramos y duraciones, nunca identificadores, importes, cuerpos o credenciales.

La ruta de pagos conserva autenticación inicial y final con revocación/reset, roles, perfiles, casillas, revisión/digest, propiedad, lecturas RTDB como usuario, pertenencia e integridad de cada fuente y cobertura. Cada autenticación emite un contexto privado que puede consumirse una vez para leer sus registros exactos, en lugar de volver a descargar inmediatamente perfiles/permisos. Las APIs generales siguen usando contexto fresco como antes. El original autorizado lleva una prueba privada de objeto, actor y hash; el lector reutiliza esa lectura inicial y vuelve a contrastarla. No hay autoridad basada en JSON ni caché entre peticiones. La lectura final también pasa por las reglas del usuario, además de comprobar propiedad. No cambia ningún escritor ni importe.

El adaptador del router nativo se amplía en tres fragmentos cerrados: propósito de respuesta, selección de la lectura para pagos y puerto readAsUser de su constructor. Restaurarlos produce el hash nativo original exacto. No se sustituye el router publicado por la copia Git. Se añade commercial-ownership.js a la imagen sólo después de comprobar que la fuente nativa previa coincide con la base de ese módulo.
