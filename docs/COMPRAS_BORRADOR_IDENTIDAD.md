# Eliminación de borrador por identidad interna

El número visible de una orden no identifica unívocamente el registro. La revisión permite conservar una orden recibida y eliminar un borrador con el mismo número, siempre que sus claves internas sean diferentes y se cumplan las comprobaciones existentes.

El servicio dedicado mantiene también el índice de vínculos instalado. El derivador puro aplica cambios acotados a Guard, Store, servidor y revisión; su reversa recupera todos los bytes originales. Conserva los demás módulos nativos y usa los proyectores existentes, sin habilitar índices financieros globales ni modificar reglas.

Validación: prueba del paquete nativo con órdenes ficticias del mismo número, repetición idempotente, stock físico y orden recibida intactos, equivalencia del índice con reconstrucción completa, cero lecturas financieras para este cambio no financiero. Una segunda prueba usa REST real del emulador con las reglas vigentes: comando autorizado aceptado y escrituras SDK no coordinadas rechazadas. No se eliminó una orden productiva como prueba.

Los permisos, captura revisada, vigencia, hashes de originales e inventario y nueva comprobación antes de guardar siguen siendo obligatorios. El despliegue y la disponibilidad productiva se documentan por separado después de verificarlos.
