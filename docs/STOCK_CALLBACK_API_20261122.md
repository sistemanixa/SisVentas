# Callback implementado para A/D y resumen para C

Contrato de ACK actualizado: execute sólo retorna éxito tras guard.run confirmado/replay válido y añade `id=body.id`, `digest=Reference.digest(body)` al resultado (sin aceptar digest en body). El resultado prospectivo del plan lleva committed=true para que el resolver nativo existente pueda clasificar el recibo confirmado; nunca se envía a UI antes de persistir/replay. recover añade también id/digest a la respuesta y al resultado confirmado. No confundir ese digest de transporte con expectedHashCAS.

Recuperación nativa opcional: create admite `resolveOperation=servicioExistente.resolve` (no un callback del cliente). Si no hay recibo, puede invocar el resolver existente labor-write-gateway.resolve con el mismo ID/digest; únicamente si éste acredita rechazo y el recibo genérico contiene SV_LABOR_CANCELLED/committed=false se devuelve cancelled/definitiveNonCommit. El componente no fabrica cancelaciones ni recibos. Sin ese helper o sin prueba definitiva retorna uncertain/pending y conserva el intento; una ejecución tardía que encuentra cancelación nativa se rechaza y nunca se transforma en éxito. Prueba compuesta con resolver nativo y guard real incluye ese caso. No se registró ninguna ruta HTTP.

Export real: `require('./office-stock-reference-port').createReferenceResolver({enabled=false, loadCoverage})` retorna `resolveReference(original, ports)`. Export separado `assertFresh(readSet, readFresh)` para registrar en beforeCommit. Ningún consumidor ni handler se conecta en este incremento.

## A/D: original y puertos

original es `{purpose:'stock'|'purchase'|'ot', path, selector?, record?, expectedOriginalHash?}`. path es la ruta exacta del ORIGINAL de servidor en inventario_operativo/ordenes/listas_materiales/ordenes_trabajo y su clave; selector es fila/clavestable validada por el dueño. record puede ser el documento ya leído por el servidor (incluidos productoKey/codigo históricos); el callback lo compara con la relectura del original. No se acepta catálogo pre-resuelto ni productKey/identity/hints sueltos enviados por cliente. Si la fila es histórica, pasar el documento original y extraer la fila con identifyOriginal antes de cualquier lookup de catálogo.

ports.read lee el original y demás referencias bajo scope.get/track del dominio. ports.track(path,value), opcional, permite agregar cada lectura al conjunto CAS existente. ports.identifyOriginal(stored,selector) es el extractor interno del propietario: valida pertenencia y devuelve productKey histórico opcional, inventoryKey, receiptIdentityKey y aliases opcionales derivados EXCLUSIVAMENTE del original (sin catálogo previo). ports.legacy(document) es el recorrido actual; el adaptador A/D conserva sus normalizaciones y semántica. ports.access opcional agrega contexto de autorización ya comprobado por el escritor. query queda disponible al propietario, pero este callback no necesita consultas raíz ni puede inventar cobertura de consultas parciales.

OFF devuelve exactamente ports.legacy(record si se pasó, si no original), sin lectura ni carga de cobertura extra. ON lee/verifica original y cobertura, busca ambos sentidos por las identidades históricas; si NO hay mapping devuelve el resultado legacy sobre el original fresco conservando las3claves y metadatos del dominio. Agrega mapped=false/mappingRevision0/readSet. Error de lectura, cobertura incompleta o asociación huérfana jamás equivale a ausencia.

Con mapping, primero resuelve la inversa histórica y sólo después consulta el catálogo canónico mediante loadSnapshot. Comprueba forward/inverse/identidad/candidatos y conserva receiptIdentityKey. Resultado `{productKey, inventoryKey, receiptIdentityKey, mappingRevision, status, mapped, readSet}`. readSet es privado, lista `{path,hash}` (no cantidades/ledger crudo); assertFresh relee cada ruta y rechaza cualquier diferencia. A/D deben llamarlo bajo la coordinación y no convertirlo en respuesta de UI. No se modifica un byte de los originales. Cualquier cambio de mapping mientras se calcula un delta invalida el CAS.

loadCoverage debe soportar fase consumer-lookup para las identidades históricas antes del catálogo, además del contrato normal de loadSnapshot. Debe leer evidencia de servidor en sv_stock_reference_config/index y respaldar cobertura completa de catálogo/inventario/mapping/owners/receiptIdentity y generación; sin evidencia leída falla cerrado. Aún NO existe preparación autoritativa productiva del índice: las pruebas usan datasets ficticios completos como doble. No hay complete=true cliente ni activación de barrera real. Tooling de preparación de ramas/prefijos/colisiones y validadores sigue en el núcleo; consumidores deben mantener OFF hasta ese cierre.

## C: preview y recuperación

preview conserva expectedHash CAS y añade `product:{key,name,code,unit,status}` e `inventory:{key,label,quantity,unit}` desde el snapshot fresco. Cantidad validada sin redondeo; sin costos, historial, readSet ni JSON de ledger. Falta de unidad se identifica, no se inventa. Los puertos UI siguen searchProducts/preview/execute/recover/context/onSaved inyectados, sin ruta HTTP.

recover(identity,{id,digest}) consulta el recibo genérico propio con digest CANÓNICO DEL CUERPO ORIGINAL. No usar expectedHashCAS como digest de transporte. Sin recibo ni helper nativo devuelve uncertain (nunca notfound/abortado); la UI mantiene ID/cuerpo y permite consultar/reintentar. Con helper nativo rige el protocolo descrito arriba, incluyendo posible recibo de cancelación del coordinador existente. Si UID/digest no corresponden rechaza; resultado incompleto queda uncertain. Si el recibo está confirmado retorna su resultado original sin nueva escritura y sin exigir nueva cobertura/barrera; sí revalida acceso actual. onSaved es responsabilidad de la UI sólo tras confirmación; el núcleo no lo dispara por incertidumbre. Default OFF también se respeta para recuperación.

## Evidencia

Pruebas callback: OFF sin reads, ausencia preserva legacy, inversa antigua antes de catálogo inexistente, identidades distintas, CAS del original/inventario/catálogo/cobertura/mapping, original falso, inversa huérfana, lectura denegada e identidad histórica alterada. Pruebas command agregan resumen fresco y digest transporte vs CAS/recover uncertain/confirmed. Sin navegador, red, reglas remotas o writes reales. El primer ensayo tuvo un error de sintaxis en la fixture del callback; corregido sin alterar expectativas.
