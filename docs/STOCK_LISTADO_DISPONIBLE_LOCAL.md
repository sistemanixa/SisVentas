# Stock: listado disponible y alta desde catálogo · local, 08/11/2026

El listado muestra únicamente cantidades disponibles mayores que cero. Cero, ausencia de conteo y referencias ambiguas no se presentan como existencias positivas. Se conserva la paginación existente por bloques de 50 productos: «Ver más» recorre la continuación, no se afirma haber cargado todas las existencias al leer un bloque. No se añadió una descarga automática de todo el inventario.

«Agregar stock» busca productos activos del catálogo, incluso los que no tienen stock. Carga el catálogo mediante el circuito existente de Productos y espera SVDataReadiness; cancelar cierra y cancela la espera. Se excluye mano de obra con el criterio canónico. Los metadatos del selector no sirven como cantidad: al elegir se consulta el detalle autorizado actual. Si existe un conteo se suma la cantidad ingresada; si no existe se pide el conteo inicial, sin fingir un cero histórico. Motivo obligatorio. El lápiz conserva el ajuste absoluto, incluido cero para retirar el producto del listado. Suma decimal comprobada sin descartar precisión.

El comando y las rutas del servidor no cambiaron. Se conserva expectedHash, identificador estable, recuperación y rechazo de concurrencia. Si la recuperación de una respuesta perdida sólo confirma el recibo, se relee el detalle antes de reemplazar la cantidad visible; nunca se sustituye por undefined. Reservas, asignaciones, compras, precios, pagos y comisiones quedan fuera del cambio.

Pruebas focales actuales: 5/5 Chrome (sistema completo 390/1280 y respuesta perdida, selector real con catálogo cargado bajo demanda; alta de producto sin registro/cero y suma 0,1+0,2=0,3; quitar al ajustar a cero). 2/2 catálogo/cancelación/sesión. Pruebas nativas y readiness anteriores 4/4. Los intentos iniciales restringidos fallaron por red de loopback y un intento descubrió la falta de catálogo; no se cuentan como aprobados.
